# Per-company memory - Jacob's equivalent of Mary's job files

One file per company Jacob is actively working: `<slug>.md` (lowercase, hyphenated -
`lindum-group.md`). His unit of memory is the COMPANY, not the job, because a
relationship outlives any tender.

The contract mirrors `data/jobs/` (Phase 5, AGENT-AUDIT.md):

- **150 lines maximum** - detail belongs in the ledger and `data/jacob/`.
- `## Position` near the top: the relationship in a dozen lines - who they are, what
  history Fenster has (won/quoted/cold), who the named contact is, what is live now.
- Then: what we are trying to make happen / last contact and what was said /
  next action and who owns it / what Adam decided about them.
- Create the file the first time a company gets real attention (a call recommended, a
  draft written, a question to Mary). Update it before close-out. Do not create files
  for list-rows nobody is working - a file is a claim that somebody cares.

History without a file: `python scripts/mary_recall.py --grep "<company>"` searches
everything either bot has recorded.
